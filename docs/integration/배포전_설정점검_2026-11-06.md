# 배포 전 로컬 설정 점검 — 2026-11-06

실제 배포·외부 서비스 연결은 하지 않았다. 이 문서는 현재 코드에서 확인한 조건이며 Render·EC2에서 동작했다고 보증하지 않는다.

## 이번 변경

공유용 `.env.example`에 자격증명 형태의 값과 중복 설정·터미널 명령이 들어 있어 예제 파일을 빈 값 중심으로 정리했다. 실제 `.env`는 변경하지 않았다. 기존 값이 실제 자격증명이라면 DB 비밀번호, 인증 SECRET_KEY, 외부 API 키를 재발급해야 한다. 예제 파일 정리만으로 이전 Git 이력이나 공유본의 값이 무효화되지는 않는다. 이번 작업에서는 자격증명 재발급·Git 이력 변경을 하지 않았다.

## 코드에서 확인한 배포 조건

| 대상 | 현재 설정 | 배포 전 할 일 |
| --- | --- | --- |
| API | render.yaml의 rootDir는 Semiproject-front/backend, uvicorn app.main:app --host 0.0.0.0 --port $PORT | 실제 서비스 환경변수·DB 연결 확인 |
| 프론트 | frontend와 ai-fashion을 함께 빌드해 frontend/dist 및 dist/ai-fashion 제공 | npm ci와 두 앱 빌드, public 모델 파일도 배포되는지 확인 |
| API 주소 | render.yaml에 예시 onfit-api.onrender.com 주소가 고정됨 | 실제 배포한 API 주소로 VITE_API_BASE_URL 설정 후 다시 빌드 |
| AI 패션 API | VITE_API_URL 또는 VITE_API_BASE_URL에서 /api를 제거한 주소 사용 | 두 앱 빌드 시 같은 API 환경 설정 전달 |
| CORS | FRONTEND_ORIGINS의 쉼표 구분 목록 사용 | 실제 프론트의 HTTPS origin 등록, 경로·끝 슬래시 제외 |
| 인증·DB | SECRET_KEY와 DATABASE_URL 또는 TIDB_* 사용 | 새 비밀값과 TLS 설정, DB 접근 허용 확인. 비밀값을 VITE_*에 넣지 않음 |
| OCR | Python 패키지 외에 Tesseract 실행 파일과 kor/eng 데이터 필요 | 배포 OS에 별도 준비하지 않으면 이미지 OCR은 미지원 상태로 남음 |
| 자동 수집 | render.yaml의 run_once 경로는 존재하나 실행 내용은 안내 로그뿐 | 실제 가격 수집이 구현·연결됐다고 표시하지 않음. 담당 팀원과 연결 필요 |

## EC2에서의 구조

프로덕션에서는 Vite 개발 서버 대신 빌드된 frontend/dist를 정적 서버로 제공하고, FastAPI를 별도 프로세스로 실행한다. 같은 도메인의 `/api`와 `/health`를 FastAPI로 전달하면 프론트 API 주소를 `/api`로 사용할 수 있다. `/models`, `/textures`, `/ai-fashion`도 정적 파일로 제공해야 한다. HTTPS·프로세스 자동 시작·리버스 프록시는 아직 구성하거나 검증하지 않았다.

## 확인 결과와 남은 검증

- 앞 단계의 메인·AI 패션 코드 빌드는 성공했다. 실제 배포용 public 파일 복사와 호스팅 검증은 별도다.
- 프론트 코드의 문자열 형태 `/models`·`/textures` 경로 24개를 점검했다. `ONFIT_Human_Male.glb` 경로 파일이 없으므로 남성형 전용 옵션이 활성화되지 않는지 배포 전 확인해야 한다. 동적 생성 경로나 외부 이미지 URL은 이 검사에 포함되지 않는다.
- 실제 TiDB HTTP 저장·재로그인·백엔드 재시작 후 조회는 로컬에서 통과했다.
- 브라우저 실제 조작·3D 육안 확인, 외부 배포 환경, OCR, 팀원 수집 연동은 미검증 또는 미연결이다.
- commit/push/merge/배포는 수행하지 않았다.
