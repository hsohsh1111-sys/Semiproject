# 가입 전 약관 동의와 기록 — 2026-11-12

## 화면 흐름

회원가입 클릭 → 약관 동의 → 필수 항목 확인 후 계속 → 아이디·닉네임·휴대폰 번호·비밀번호 입력 → 가입.

- 필수: 만 14세 이상 자기 확인, 서비스 이용약관, 개인정보 수집·이용.
- 선택: 이벤트·혜택 문자 수신. 거부해도 가입 가능. 전체 동의는 선택 항목까지 함께 선택하지만 개별 해제 가능.
- 보기 버튼은 해당 안내 내용을 펼친다. 실제 제공하지 않는 야간 광고·제3자 제공 동의는 임의로 추가하지 않았다.
- 휴대폰 라벨은 `휴대폰 번호`이며 아래 설명은 삭제했다. 번호 소유 인증·문자 발송은 구현하지 않는다.

## 서버와 DB

- 휴대폰 가입의 필수 동의 3개를 서버에서도 검증한다. 프론트 버튼만으로 차단하지 않는다.
- 사용자가 승인한 users.signup_consent JSON(nullable)을 실제 TiDB에 추가했다. 기존 회원 수는 유지했으며 과거 회원에게 소급 동의 기록을 만들어 넣지 않았다.
- 신규 휴대폰 가입 시 필수/선택 동의 내역, 서버 UTC 시각, 서버가 정한 약관 버전(`2026-11-12-draft-1`)을 저장한다. 클라이언트의 임의 버전·동의 시각은 받지 않는다.
- 초기 가입 동의의 스냅샷이다. 향후 약관 개정·재동의·동의 철회/변경 이력을 누적 보관하는 별도 절차는 아직 구현하지 않았다. 모든 기업의 운영·법적 요건과 동일하다고 보장하지 않는다.
- 마이그레이션: database/migrations/20261112_signup_consent.sql. 동일 DB에 중복 실행하지 않는다.

## 문구 관리와 한계

SignupTerms.jsx의 notices에 현재 안내 초안을 둔다. 정식 운영 전에 운영 주체, 이용약관, 개인정보 보유기간·탈퇴/삭제 요청 절차 등 실제 운영 정책을 확정해야 한다. 초안이라는 점은 보기 내용에도 표시한다. 안내 내용이 바뀔 때 서버 저장 버전도 함께 변경하고 이전 내용을 보관해야 한다.

## 검증

- 관련 백엔드 41개: 필수 항목 거부·타입 검증·서버 버전 기록·선택 동의 거부 가입·기존 회원/관리자 회귀.
- 프론트 인증/세션 14개, 코드 빌드(write:false) 통과.
- 가상 API를 사용한 headless Chrome에서 약관 선행 화면, 전체 동의, 필수 버튼 차단, 선택 해제 후 진행, 내용 보기, 휴대폰 라벨 및 부가 설명 제거, 동의 요청 데이터·모바일 레이아웃 확인.
- 실제 공동 DB 신규 회원 생성·문자 발송·운영 배포는 하지 않았다. 커밋·푸시 미실시.
