# 인바디 → 추정 체형 연결

## 2026-11-09 변경 — 네 번째 ‘나의 인바디 체형’

아래의 세 프리셋 선택 방식은 이전 구현 이력이다. 현재는 기존 세 버튼을 그대로 유지하고, 네 번째 ‘나의 인바디 체형’을 추가했다. 인바디 확인·계산·적용 전에는 입력 필요 상태다. 적용 후 다른 프리셋으로 전환했다가 네 번째 버튼을 누르면 마지막으로 계산한 개인 체형을 복원할 수 있다. 계정 전환 시 개인 체형은 정리하며 별도 DB 저장·페이지 재접속 복원은 하지 않는다.

Python 응답에 `personalized_measurements`와 `composition`을 추가했다. `preset`은 과거 클라이언트용 호환 필드로만 유지하며 새 화면은 그 값으로 체형을 선택하지 않는다. `rule_version`은 `continuous-visual-v2`다. 프론트에는 추정 공식을 복제하지 않고 검증·적용만 한다.

체중과 골격근량을 기준 키의 제곱 비율로 정규화하고 체지방률과 함께 tanh 기반의 연속 가중치로 변환한다. 어깨·가슴·허리·복부·골반·엉덩이·허벅지 조절값과 lean/muscular/복근 가중치를 조합한다. **기준값과 계수는 시각화용 개발 값으로 인체 실측·의학적 근거에 보정되지 않았다.** 부위별 cm 출력은 모델 조절용 추정값이며 사용자 실측으로 간주하지 않는다. 정확한 실측을 입력하면 수동 보정할 수 있다.

기존 bodyBuild 문자열 프리셋은 그대로 유지하고, 개인 체형만 `kind: inbody` 객체의 소수 가중치를 사용한다. 기존 GLB의 실제 Morph Target만 조합하며 새 메시나 GLB 파일은 만들지 않는다. 의류에도 기존 공유 가중치 경로를 사용한다. 높은 체지방·성별·연령별 지방 분포의 재현 한계는 유지한다.

네 번째 버튼 옆과 인바디 적용 영역에는 다음 문구를 표시한다.

> 인바디 수치를 바탕으로 생성한 추정 체형으로, 실제 체형과 다를 수 있습니다. 세부 치수를 조절해 보정해 주세요.

검증: 백엔드 관련 38개 통과. 프론트 관련 17개 및 추가 의류 정점 검사 통과(개인 체형 파일 4개 테스트 재실행 포함). 인체·티셔츠 실제 정점의 소수 가중치 변화와 기본값 복원 확인. 두 프론트 코드 빌드 성공. 실제 로컬 HTTP에서 서로 다른 입력이 서로 다른 개인 체형을 반환함도 확인했다. 실제 사용자 결과지의 인식 정확도·브라우저 육안·관통 품질·Render 반영은 미검증이다.

## 사용자 동선

로그인 → 인바디 파일 선택 → 수치 추출 → 키·체중·골격근량·체지방률 확인/수정 → 원본 대조 체크 → 확인한 수치로 체형 제안받기 → 제안 확인 또는 다른 체형 선택 → 추정 체형을 마네킹에 적용. 적용 후 세부 치수를 직접 바꿀 수 있다. 기록 저장은 측정 시각을 입력하고 별도 버튼으로 수행한다.

저장된 기록은 파일을 다시 올리지 않아도 최근 기록 목록에서 불러와 같은 제안을 받을 수 있다. 제안·마네킹 적용만으로 DB를 저장하거나 기존 기록을 변경하지 않는다. 모호하거나 빠진 수치는 임의로 채우지 않으며 사용자가 보완해야 제안을 받을 수 있다.

## 실제 구현

- Python `backend/app/features/inbody/body_preview.py`: 확인한 네 수치를 검증하고 기존 slim/average/muscular 프리셋 중 하나를 선택.
- `POST /api/inbody/body-preview`: 인증 필요, measurements·preset·reasons·limitations·rule_version·approximate·requires_confirmation 응답. DB 쓰기 없음. 기존 API 필드·DB 스키마 변경 없음.
- `extraction.py`: 공백이 섞인 한글 항목, 같은 줄의 여러 명시적 항목, 항목 바로 다음 줄의 단일 숫자를 지원. 참조 범위·목표체중·상충하는 여러 숫자는 자동 선택하지 않는다. 원문·파일은 DB에 저장하지 않는다.
- 프론트 `inbodyBodyPreview.js`: Python이 선택한 프리셋과 확인한 키·체중을 기존 마네킹 입력에 연결. Python 분류 공식을 JS에 중복 구현하지 않는다.
- `InbodyUploadPanel.jsx`, `FittingPage.jsx`, `inbodyUpload.js`: 수치 수정·제안 조회·선택·적용·최근 기록 동선. 입력을 수정하면 이전 제안을 폐기한다. 적용 시 의류 고정 사이즈 모드를 해제해 기존 신체·의류 프리셋 변형을 재사용하며 카메라 상태는 변경하지 않는다.

## 중요한 정확도 한계

**visual-example-v1은 제품 시연용 규칙이다. 인바디 제조사 기준, 성별·나이별 표준, 의학적 체형 판정이나 실측 복원이 아니다.** 규칙은 UI의 ‘제안 기준과 한계’에도 공개한다.

1. 골격근량/체중 >= 0.45 및 체지방률 <= 20 → 근육형 예시.
2. 위 조건이 아니고 체중/(키m²) < 20 및 체지방률 < 30 → 마른 체형 예시.
3. 나머지 → 보통 체형 예시.

숫자는 검증된 의료 임계값이 아니라 기존 세 시각 자산을 선택하는 개발 규칙이다. 부위별 치수·복근·어깨너비를 실제 측정한 것으로 취급하지 않는다. 높은 체지방에 맞는 전용 자산이 없어 보통 예시로 대체하고 한계를 안내한다. 사용자 재선택이 가능하며 질병·정상/비정상·구매 사이즈를 판정하지 않는다. 현실적인 체형을 주장하려면 성별·나이·기준 데이터·다양한 결과지·실측 비교로 별도 보정해야 한다.

## 검증과 미검증

- 추출/모호함 처리/체형 제안/인증/입력 오류/DB 미저장 백엔드 테스트 31개 통과.
- 프리셋 매핑·사용자 재선택·실제 GLB 정점 변형·카메라 관련 프론트 테스트 13개 통과.
- 메인·AI 패션 코드 빌드 성공.
- 이미지 OCR 테스트는 모의 인식 텍스트를 사용하는 기존 검사를 포함한다. 실제 OCR 엔진의 새 버전·실제 사용자 파일·표 인식 정확도는 이번에 검증하지 않았다. 화면 캡처만으로 원본 결과지의 실패가 해결됐다고 주장하지 않는다.
- Docker의 합성 이미지 검사와 Render의 실제 OCR/새 API/브라우저 적용은 재배포 후 별도 확인해야 한다.
