## 공통 파일 충돌 해결

### 로그인 응답과 토큰

팀원 모달은 회원가입·로그인에서 `{access_token,user}`를 함께 받는 형태였지만, 기존 API는 가입 시 회원 정보, 로그인 시 토큰, `/auth/me`에서 회원 정보를 반환한다. 백엔드를 재개발하지 않고 `frontend/src/services/auth.js`가 가입→로그인→본인 조회 순서로 연결한다.

`App.jsx`의 메모리 세션을 헤더와 피팅에 전달해 로그인·로그아웃을 공유한다. 토큰·비밀번호를 새로 localStorage에 저장하지 않는다. 피팅의 기존 회원별 탭 치수 보관 방식은 유지한다. 팀원 `AuthModal.jsx`와 `Header.jsx`는 통합 대상 복사본에서만 이 계약에 맞췄다.

### DB 모델과 자동 DDL

현재 확정 모델은 `app/db/models/user.py`의 `users.name`, 팀원 모델은 `app/models.py`의 `users.display_name`을 사용한다. 두 User 모델을 동시에 등록하면 중복 테이블·컬럼 충돌이 발생할 수 있으므로 팀원 User 모델·별도 Base·인증 백엔드를 덮어쓰지 않았다.

팀원 `main.py`의 시작 시 `create_all`/`ALTER TABLE` 실행은 가져오지 않았다. 기존 DB 모델·세션·JWT 형식을 유지했고, 관리자 데모의 읽기 전용 `/api/auth/public-members`는 현재 User에 맞춘 어댑터로 연결했다. 마스킹된 이름/이메일만 반환하는 팀원 응답 형식을 유지한다.

**실제 공동 TiDB가 display_name을 사용한다면 바로 호환된다고 볼 수 없다.** 공통 DB 담당자와 확정 ERD를 대조한 뒤 별도 합의가 필요하다. 이번에는 실제 TiDB 조회·마이그레이션·DDL을 실행하지 않았다.

### 환경변수·API 주소

- 실제 `.env`, 비밀번호, API 키는 팀원 폴더에서 복사하지 않았다.
- 기존 `DATABASE_URL`과 함께 팀원의 `TIDB_HOST/PORT/USERNAME/PASSWORD/DATABASE` 구성도 지원한다. TLS 검증을 유지한다. `.env`는 프로젝트 공통 파일보다 backend 파일을 우선한다.
- 메인 API 기본 주소는 `/api`. 로컬은 Vite가 8000으로 전달하며 `/health`도 프록시한다. `fitting.js`의 상태 확인은 상대 API 주소도 지원하도록 수정했다.
- AI 화면은 `VITE_API_URL`을 우선하고 없으면 공통 `VITE_API_BASE_URL`에서 `/api`를 제외한 서버 주소를 사용한다. 브라우저에 서버 비밀 키를 넣으면 안 된다.
- OpenAI SDK·BeautifulSoup·Playwright 등 누락된 실행 패키지를 설치했다. GPU 모델·대용량 AI 가중치·Playwright 브라우저 바이너리는 설치하지 않았다.

## 빌드와 배포 설정

`frontend` 위치:

```powershell
npm.cmd run check:site
npm.cmd run build:site
```

`check:site`는 두 앱의 코드를 메모리에서 빌드하므로 임시 모델 복사 폴더를 만들지 않는다. `build:site`는 메인 `frontend/dist`와 그 아래 `ai-fashion/`에 실제 정적 사이트를 만든다. 기존 `npm run build`는 메인 앱만 빌드한다.

`render.yaml`의 rootDir은 실제 Git 저장소 구조인 `Semiproject-front/backend`, `Semiproject-front/frontend`로 맞췄다. 프론트 배포 명령은 두 앱 의존성 설치 후 `build:site`다. Render·EC2·Netlify 실제 배포나 자동 배포 성공은 검증하지 않았다. 실제 배포에서 API 주소·CORS·TiDB 설정을 다시 확인해야 한다.
