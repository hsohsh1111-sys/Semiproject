# ONFIT 백엔드 파일별 기능 안내

작성 기준: **2026-11-17**, 현재 로컬 프로젝트의 실제 코드를 확인해 정리했습니다.

이 문서는 파일 이름만 보고 역할을 파악하기 어려울 때 사용하는 안내서입니다. 아래 경로는 별도 표시가 없으면 **`Semiproject-front/backend/` 기준**입니다. VS Code에서 `Ctrl+P`를 누르고 파일 경로를 입력하면 찾을 수 있습니다.

> **코드가 있다는 것과 실제 운영 검증이 완료됐다는 것은 다릅니다.** 샘플 응답·준비용 인터페이스·외부 서비스 설정이 필요한 코드는 구분해서 적었습니다. 이번 작업에서는 문서만 작성했으며 서버 실행, DB 변경, 실제 AI 호출이나 테스트 재실행은 하지 않았습니다.

## 먼저 보기 — 3D 가상 피팅 관련 파일

**3D 화면과 마네킹·옷을 실제로 움직이는 핵심은 프론트엔드입니다.** 백엔드의 `fitting` 폴더는 계산을 담당합니다. 따라서 3D 기능을 찾을 때 백엔드 파일만 보면 전체 흐름이 보이지 않습니다.

이 절의 경로는 **`Semiproject-front/` 기준**입니다.

### 문제별로 어디를 보면 되는가?

- **슬라이더를 움직여도 신체가 안 변함:** `FittingPage.jsx` → `GlbMannequinModel.jsx` → `bodyMorphs.js` → 실제 GLB의 Morph Target.
- **몸은 변하는데 옷이 안 따라옴:** `GlbMannequinModel.jsx` → `GarmentGlb.jsx` → `garmentGlb.js` → 해당 의류 GLB.
- **회전·확대가 초기화됨:** `GlbMannequinModel.jsx`의 카메라 연결과 `glbCamera.js`.
- **모델이 작거나 위로 치우침·키 조절이 이상함:** `glbGeometry.js`와 `GlbMannequinModel.jsx`.
- **옷 색이 안 바뀌거나 다른 모델에 영향:** `GarmentGlb.jsx`와 `garmentAppearance.js`.
- **인바디 체형 계산값이 이상함:** 백엔드 `inbody/body_preview.py` → 프론트 `inbodyBodyPreview.js` → `bodyMorphs.js`.

### 같은 파일 이름이 반복되는 이유

`auth/service.py`와 `fitting/service.py`는 다른 기능을 담당합니다. **파일 이름 앞의 폴더까지 함께 확인**해야 합니다.

| 이름 | 쉬운 설명 | 예시 |
|---|---|---|
| `router.py` | 프론트 요청을 받는 입구. 주소·HTTP 메서드·인증·응답 형식을 연결 | `/api/inbody/extract` 요청을 수치 추출 함수에 전달 |
| `service.py` | 요청을 처리하는 실제 업무 순서·조회·저장 로직 | 본인 인바디 기록을 DB에서 조회 |
| `schemas.py` | 입력·출력 데이터의 모양과 허용 범위 | 키·체중·체지방률 입력 검증 |
| `models/*.py` | DB 테이블·컬럼과 Python 객체의 연결 | `users`, `inbody_records` |
| `dependencies.py` | 요청 처리 전에 공통으로 필요한 검사·준비 | 로그인 여부, 관리자 권한, DB 세션 |
| `*_engine.py` | 별도로 계산·검증할 수 있는 계산 로직 | 신체 치수 변환·의류 여유분 |

## 2. 서버 시작과 공통 설정

| 파일 | 기능과 역할 | 연결·주의사항 |
|---|---|---|

| `app/core/config.py` | 환경 변수와 `.env`를 읽어 설정 객체 생성. TiDB 개별 항목으로 DB URL 구성, 인증 키 설정 여부 확인 | 실제 비밀번호나 키를 코드에 적는 파일이 아님. 외부 AI 서비스 중에는 `os.getenv()`로 직접 설정을 읽는 파일도 있음 |
| `app/core/security.py` | 비밀번호 해시 검사, 일반 회원 JWT 발급·검증, 만료·발급자·대상·토큰 종류 검사 | 관리자 토큰 로직은 `admin_auth.py`에 별도로 존재 |
| `requirements.txt` | FastAPI·SQLAlchemy·OCR·Playwright·OpenAI SDK·pytest 등 Python 의존성과 버전 범위 정의 | 패키지 목록이며 기능 실행 코드는 아님 |

| 파일 | 기능과 역할 | 대표 연결·상태 |
|---|---|---|
| `app/features/auth/router.py` | 가입, 가입 후 자동 로그인, 회원·관리자 통합 로그인, 본인 정보, 계정 조회·탈퇴, 관리자 세션, 이메일 인증 API 입구 | `/api/auth/*`. 입력 오류 응답에 민감한 원문이 노출되지 않도록 처리하는 `PrivateValidationRoute`도 정의 |
| `app/features/auth/service.py` | 회원 생성, 중복 처리, 비밀번호 해시 저장·검사, 회원 인증. 가입 시 연락처·선택 수신 동의·약관 동의 기록 저장 | 일반 회원 DB 처리. 관리자 설정 계정 로그인과 구분 |

| `app/features/auth/dependencies.py` | 인증 설정·DB 준비 확인, Bearer 토큰 추출, 현재 회원 조회, 관리자 여부·관리 권한 검사 | 회원 전용 기능은 `get_current_user`, 관리 기능은 `require_admin` 등을 사용 |

| `services/recommendation_service.py` | 검색 후보의 이미지를 안전하게 가져오고 비교용 이미지 구성. 원본 선택 상품과 후보를 비전 모델로 비교해 결과 구성 | 이미지 호스트 검사·캐시·동시 요청 제한 등 포함. 외부 검색·모델 설정 필요 |

| `data/musinsa_fashion_vision_prompt.txt` | 이전 버전 상품 분석 지침 | 현재 `vision_prompt.py`의 직접 참조 대상은 v2. 이 문서만 보고 삭제하지 않기 |


## 13. `__init__.py`와 실행 기능이 없는 파일

`app/`, `app/api/`, `app/core/`, `app/db/`, `app/db/models/`, `app/features/`와 각 기능 폴더, `app/schemas/`, `app/services/`, `app/crawlers/` 및 하위 폴더, `tests/`에 있는 `__init__.py`는 Python 패키지 구분이나 간단한 설명을 위한 파일입니다.

현재 이 파일들에는 별도 API·신체 계산·DB 조회 업무가 들어 있지 않습니다. 그래도 패키지 구조에 사용하는 파일이므로 **파일이 짧거나 비어 있다는 이유만으로 삭제하지 않습니다.**

## 15. 기능을 따라 읽는 순서

백엔드가 처음이라면 모든 파일을 한 번에 읽기보다 **화면에서 한 동작을 골라** 따라가면 이해하기 쉽습니다.

1. **로그인:** `auth/router.py` → `auth/service.py` 또는 `admin_auth.py` → `core/security.py` → 회원 모델.
2. **인바디 분석:** `inbody/router.py` → `extraction.py` → `schemas.py` → 추출값을 받아 표시하는 프론트.
3. **나의 체형 계산:** `inbody/router.py` → `body_preview.py` → 개인화 치수·구성값 → 프론트 GLB 매핑.
4. **피팅 API 계산:** `fitting/router.py` → `service.py` → `body_engine.py` + `garment_engine.py` → 응답.
5. **기록 불러오기:** `inbody/router.py` → `service.py` → `db/models/inbody_record.py` → DB 세션.
6. **사진에서 상품 찾기:** `routers/circle_search.py` → `vision_service.py` → `recommendation_service.py` + `musinsa_service.py`.

핵심은 **요청 입구(router), 처리 순서(service), 데이터 검증(schemas), DB 구조(models), 화면 렌더링(frontend)**의 역할을 구분하는 것입니다.
